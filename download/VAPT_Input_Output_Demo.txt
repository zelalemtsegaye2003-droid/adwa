────────────────────────────────────────────────────────────────────────────────
0. THE THREE INPUTS (always in this order)
────────────────────────────────────────────────────────────────────────────────

(1) ASSETS — the attack-surface registry (POST /api/vapt/assets)
    { "name": "Core switch pair (DC-1)", "kind": "NETWORK",
      "identifier": "10.1.1.10",            ← IP / hostname / host:port / URL
      "environment": "PROD", "surface": "INTERNAL", "criticality": "critical",
      "osOrPlatform": "Cisco IOS-XE 17.6" }

    kind decides which live engine runs:
      NETWORK / FIREWALL → TCP/TLS INFRA engine + SNMP device audit (UDP)
      DATABASE           → INFRA engine + credentialed DB wire-protocol audit
                           (MongoDB OP_MSG/SCRAM, MySQL/MariaDB handshake)
      WEBAPP / API       → DAST engine (real HTTP checks against the URL)
      other kinds        → INFRA engine (ports, banners, TLS, exposures)

    Optionally attach SCAN CREDENTIALS (AES-256-GCM at rest, never echoed):
      "credentials": [
        { "kind": "mysql", "username": "audit", "secret": "…" },
        { "kind": "mongo", "username": "audit", "secret": "…" },
        { "kind": "snmp",  "username": "community", "secret": "…" } ]

(2) SCOPE — written authorization (POST /api/vapt/scopes, then a SECOND user
    approves it — four-eyes). No scan or discovery EVER runs outside one:
      { "name": "Q1 core-banking assessment",
        "targets": [{ "kind": "cidr", "value": "10.2.6.0/24" },
                    { "kind": "domain", "value": "cbe.com.et" },
                    { "kind": "url", "value": "https://app.bank.et" }],
        "authorizationNote": "CISO written authorization ICT-SEC-2026-114",
        "validFrom": "…", "validUntil": "…" }

(3) THE RUN — scans or discovery, both behind the same gate.

────────────────────────────────────────────────────────────────────────────────
1. SCAN — POST /api/vapt/scans
────────────────────────────────────────────────────────────────────────────────
INPUT:
  { "scanType": "FULL",        ← DISCOVERY | INFRA | DAST | FULL
    "profile":  "SAFE",        ← SAFE (default) | INTRUSIVE (four-eyes opt-in)
    "assetIds": ["…"],         ← optional subset; omit = whole registry
    "ports":    [1521, 8080] } ← optional extra TCP ports

OUTPUT (HTTP 201) — one record plus four live-engine report arrays:
  scan: { status: "COMPLETED", engineMode: "live", infraReal, dastReal,
          newCount, knownCount, autoClosedCount, scopeId, summary {…},
          durationMs }
  infraReports: [{ host, openPorts: [21,22,23,25,80,443,3306,…],
                   banners: [{ port, banner: "220 (vsFTPd 2.3.4)" }],
                   serviceChecks: [{ id: "redis-unauth", hit: true }] }]
  snmpReports:  [{ host, port: 161, reachable, versions: ["v2c"],
                   defaultCommunities: ["public","private"],
                   system: { sysDescr: "Cisco IOS Software…", sysName: "…" },
                   v3: "noAuthNoPriv" | "authRequired" | "none" }]
  dbReports:    [{ host, port: 27017, protocol: "mongo",
                   mongo: { authEnabled: false, version: "4.0.10",
                            databases: ["bankdb","corebanking",…],
                            scramOk: true } },
                 { host, port: 3306, protocol: "mysql",
                   mysql: { authEnabled: true, version: "5.5.62-MariaDB",
                            loginOk: true } }]
  dastReports:  [{ target, reachable, checks: [{ id: "hsts", result: "fail" }] }]

  REJECTION (HTTP 403) when any target is outside an approved scope:
    { error: "Scan rejected by the authorization gate — …",
      unauthorized: [{ asset, identifier }],
      remediation: "Create a scope covering these targets …" }
    → the attempt is recorded in the hash-chained audit log (SCAN_REJECTED).

PERSISTED FINDINGS (GET /api/vapt/vulnerabilities) — every row carries:
  • cveId (banner→feed version match: real CVSS v3.1 vector, EPSS score,
    CISA KEV flag) or a live posture finding
  • severity + priorityScore (CVSS × EPSS × KEV × asset-criticality)
  • evidence — the literal bytes/transcript observed, e.g.
      { mode: "snmp-live", sysDescr: "Cisco IOS …",
        transcripts: ["GET public@v2c → sysDescr=…"] }
      { mode: "db-live", databases: ["bankdb"], version: "4.0.10",
        transcripts: ["listDatabases succeeded WITHOUT authentication…"] }
  • remediation guidance + SLA due date (30/60/90/180-day policy)
  • fingerprint (sha256 asset‖rule‖location) — dedup + auto-close on rescan

────────────────────────────────────────────────────────────────────────────────
3. GOVERNANCE OUTPUT (always on)
────────────────────────────────────────────────────────────────────────────────
  Hash-chained audit log (GET /api/vapt/audit?verify=1):
    SCAN_STARTED / SCAN_COMPLETED / SCAN_FAILED / SCAN_REJECTED /
    SCAN_PROFILE_BLOCKED / FINDING_DEDUPED / FINDING_AUTOCLOSED /
    CHECK_CREATED / CHECK_TESTED / CHECK_REJECTED /
    DISCOVERY_RUN / DISCOVERY_REJECTED        ← who, what, target, when, result
  Tamper verification recomputes the whole chain (sha256 row-by-row).
